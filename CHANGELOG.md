# Changelog

All notable changes to this scaffold should be documented here.

## 0.6.0

### Added
- Kilo as the seventh harness adapter at **Full** tier. Kilo reads shared `AGENTS.md` natively and supports project slash commands via `.kilo/command/*.md`, so the adapter ships 66 generated wrappers (`style: "claude"`) plus pre-wired MCP: the registry entry declares `mcp: {path: ".kilo/kilo.json", format: "kilo"}` (new `"kilo"` format in `schemas/harnesses.schema.json`), and `sync:mcp` emits an MCP-only `.kilo/kilo.json` (`$schema: https://app.kilo.ai/config.json`) so user model/permission settings still merge from `./kilo.json` or the global config. The OpenCode/Kilo embedded `mcp` object (type `local`|`remote`) lives in `scripts/lib/mcp-catalog.js` so those surfaces cannot drift; `generate-wrappers.js` uses the same helper for the OpenCode registry. Scaffold `agents/` and `skills/` are not copied into `.kilo/` — those files are workflow roles, not Kilo primary/subagent definitions. Agent Manager runtime (`.kilo/agent-manager.json`, `.kilo/worktrees/`) is gitignored. No hooks (Kilo has no PreToolUse/PostToolUse). Docs: `docs/harness-support.md` matrix row, `docs/mcp-setup.md` (status table + generated-config list), root README and `CLAUDE.md` adapter lists. `validate-structure.js` now also requires `.grok/README.md`.

### Fixed
- Kilo MCP env interpolation: `.kilo/kilo.json` now emits `{env:VAR}` (Kilo's documented config syntax) instead of OpenCode's `${VAR}`, which Kilo does not expand and would overlay a real `FAL_KEY` with the literal string.

## 0.5.0

### Added
- Grok Build (xAI's `grok` CLI) as the sixth harness adapter — the first consumer of `npm run new:harness`. Grok reads the shared `AGENTS.md`/`AGENTS.override.md` natively, so the adapter is a thin `.grok/README.md` plus pre-wired MCP: the registry entry declares `mcp: {path: ".grok/config.toml", format: "toml"}` (new `"toml"` format in `schemas/harnesses.schema.json`), and `sync:mcp` now emits a generated project-scoped `.grok/config.toml` with `[mcp_servers.*]` sections (`${VAR}` env values expanded by Grok at launch — no secrets on disk). The Codex TOML builder was refactored into a shared `tomlServerBlocks()` so both TOML surfaces stay identical, and the generated `mcp-configs/generated/README.md` pre-wired table is now derived from the harness registry instead of hand-listed. No project-scoped command support in Grok, so no wrappers (documented in the adapter README). Docs: `docs/harness-support.md` matrix row, `docs/mcp-setup.md` (status table + generated-config list), root README and `CLAUDE.md` adapter lists.
- `npm run new:harness` (`scripts/new-harness.js`): scaffold a new harness adapter the same way `new:engine` scaffolds an engine layer — validates the id, writes a thin `.<id>/README.md` that routes back to the shared scaffold, registers the harness in `manifests/harnesses.json` at the conservative "Rules only" tier, and appends the `docs/harness-support.md` matrix row and root README harness list entry; `--dry-run` supported. Covered by `tests/scripts/new-harness.test.js` (mirrors the `new-engine` test: dry-run plans without writing, invalid/duplicate ids rejected). Capabilities (commands / hooks / mcp) are then flipped in the registry as the harness's real support is confirmed, and the generators pick them up.
- Cursor command wrappers: `.cursor/commands/` now carries the 66 generated slash-command wrappers (Cursor supports project commands via `.cursor/commands/*.md`), raising the Cursor adapter from "Rules + hooks" to **Full** tier. Enabled by a one-line registry change (`commands: {dir, style: "claude"}` in `manifests/harnesses.json`) — the wrappers, drift check, and doctor entry point all followed from the registry. `docs/harness-support.md` matrix updated (and its stale "50 wrappers" counts corrected to 66); `.cursor/README.md` and a new `.cursor/commands/README.md` document the generated surface.
- Harness adapter registry (`manifests/harnesses.json` + `schemas/harnesses.schema.json`): the single source of truth for which harness adapters exist and what each supports, mirroring the `engines.json` pattern (audit 2026-06-10 observation 2.7 — harness support was undeclared and consumer lists hand-maintained). New `scripts/lib/harnesses.js` (`loadHarnesses()`, `harnessIds()`); `generate-wrappers.js` now derives which adapters get command wrappers (and in which format/location) from the registry, `generate-mcp-configs.js` derives the live project-scoped MCP config locations from `mcp.format: "universal"` entries, and `doctor.js` derives its adapter presence check from each entry's `entryPoints`. Generated output is byte-identical to before — this is a source-of-truth consolidation. Documented in `manifests/README.md`, `scripts/README.md`, `CLAUDE.md`, and root `README.md`.

### Fixed
- Spurious generated-artifact drift on Windows: with `core.autocrlf=true`, git checked text files out with CRLF while the generators emit LF, so `validate:wrappers` / `validate:mcp` failed byte comparison on files whose content diff was empty (local red, CI green — the exact local/CI divergence the validation gate exists to prevent). Two defenses: a new `.gitattributes` forces `eol=lf` for all text files (overriding local `autocrlf`), and all four drift comparators now normalize line endings through the new shared `scripts/lib/text.js` (`generate-wrappers.js` and `generate-mcp-configs.js` gain the tolerance; `validate-structure-artifacts.js` and `generate-dependency-graph.js` drop their two divergent local implementations for the shared one). Documented as TROUBLESHOOTING §13; `scripts/README.md` lib table completed (`text.js`, plus the previously missing `hook-wiring.js` and `schema-validation.js` rows).
- NebulaLance ship orientation: the generated ship model (authored in a 3/4 concept view) imported facing diagonally; hand-tuned Euler angles couldn't reliably make it horizontal because the model's nose-tail axis tilts toward the camera. Replaced with a deterministic geometry-based orientation (`orientForwardX`: PCA of the mesh — longest axis → +x, presented as a side profile with the flattest axis vertical and the wingspan toward the camera, nose disambiguated by cross-section), so the ship always faces forward (+x), reads as a side view, and only pitches up/down with vertical movement. Robust for any generated ship model, not just this one.

### Added
- `playwright` MCP server (Microsoft official, `@playwright/mcp`) in `mcp-configs/mcp-servers.json`, added to the `web` and `release` profiles: an optional interactive layer for Claude to playtest/QA web (HTML5) builds in a real browser — navigate, interact, screenshot, and read console/page errors — the work the samples currently do via a hand-run Playwright script. Disabled by default; each sample still keeps its reproducible headless smoke path. Browser-only (use an engine MCP for editor control).
- Quality/price tier selector for AI asset generation. The registry gained `defaultQuality` (default `balanced`) and a per-capability `byQuality` map (`budget` / `balanced` / `premium` → model id + per-output cost); the schema enforces both. `scripts/generate-assets.js` resolves `--quality` (or `ASSET_GEN_QUALITY`, or `defaultQuality`), prints the chosen tier, estimates from its cost, and records it in the provenance sidecar; an explicit `--model` still overrides. The cost gate composes on top — budget can keep a whole video run under the threshold (Wan ~$0.25) while premium crosses it (Veo 3 ~$2.00). The agent asks the user "quality or price?" once before a batch: documented in `rules/common/asset-pipeline.md`, `/generate-assets`, the `ai-asset-generation` skill, `/full-game` Phase 5, README, `.env.example`, and the manifests/scripts READMEs. Rough spread: a full asset pass ~$2-3 budget / ~$5-7 balanced / ~$10+ premium.
- `samples/NebulaLance/` — a 2.5D side-scrolling shoot-'em-up (R-Type homage) built by one `/full-game` run: Wave Cannon charge beam, detachable Force pod (front/rear/launch, spread/laser/homing), four enemy archetypes + a three-phase weak-core boss "THE MAW", a closing-corridor turret gauntlet, power-ups, combo scoring, mobile-first finger-follow + on-screen controls and full keyboard. Strict sim/render split on a fixed timestep with a headless sim smoke (`npm run smoke` asserts a lose path and an auto-aim bot clearing all three boss phases), instanced rendering, GPU memory flat across restarts. Every visual/audio asset is fal.ai-generated via `/generate-assets` (seven Hunyuan3D models via concept→Rapid image-to-3D, nano-banana-pro key art, Seedance image-to-video menu cinematic, parallax nebula, ten ElevenLabs SFX, CassetteAI music) with `.provenance.json` sidecars and `generated-assets.json`; models swap onto the live primitives in place so it stays playable with zero generated files. Deployed at `http://51.75.26.136/nebula-lance/`
- `scripts/generate-assets.js` `--yes` flag is now parsed as the boolean it documents (the cost-gate acknowledgement); previously `--yes` errored with "requires a value" — caught by the NebulaLance asset run when the gated intro-video generation hit the gate
- More fal.ai model choices in `manifests/asset-providers.json`: `model3d` alternatives now lead with the proven `fal-ai/hunyuan-3d/v3.1/rapid/image-to-3d` and add `fal-ai/trellis-2` (PBR from one image) and `fal-ai/triposr` (fast ideation), with notes clarifying that the default stays text-to-3d for a bare prompt while the proven route is concept-image → image-to-3d; `video` adds `wan/v2.6/image-to-video` (~$0.05/s, ~$0.25 for a 5s clip vs ~$1.20 on Seedance Pro) as the budget path. Model ids verified against the fal catalog.
- Cost-confirmation gate and harness-native resolution order for AI asset generation. `manifests/asset-providers.json` gained `confirmOverUsd` (default $0.50), `nativeFirstCapabilities` (`image`, `skybox`), and per-capability `estCostUsd`; the schema enforces them. `scripts/generate-assets.js` now estimates each run's cost, prints it (including in `--dry-run`), and refuses runs at or above the threshold without `--yes` (or `ASSET_GEN_YES=1`; threshold overridable via `--confirm-over` / `ASSET_GEN_CONFIRM_OVER`) — so an agent must surface the cost and get confirmation before spending. Policy documented in `rules/common/asset-pipeline.md` (resolution order native→API→placeholder; confirm-before-spend), `/generate-assets`, the `ai-asset-generation` skill, `/full-game` (Phase 5 asks once before any spend and prefers the free native path for images), README, `.codex/README.md` (Codex `$imagegen` is the preferred image path), and the manifests/scripts READMEs.

### Changed

Reframed across `rules/common/asset-pipeline.md` (new optional-capability + no-fabrication rules), `/generate-assets` (a "Capability Gate" section up top), the `ai-asset-generation` skill, `/full-game` Phase 5 (placeholders are the default; generation is an optional in-place upgrade when a key exists), `placeholder-asset-pipeline` (the default always-available path), root README ("AI Asset Generation (optional)"), `.env.example`, `manifests/asset-providers.json`, and `manifests/README.md`. `scripts/generate-assets.js` now reports the missing key as an unavailable optional capability and points back to the placeholder commands instead of a bare error.
