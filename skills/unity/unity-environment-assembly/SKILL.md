# Unity Environment Assembly

## Purpose
Assemble a layered environment exported from Blender into a Unity (URP) level scene with a reproducible editor builder: correct axes, URP materials, backdrop, lighting, cutaways, walkable heights, breakables and gameplay wiring, verified by batch compiles and review renders.

## Use When
- a `blender-environment-pipeline` export (one FBX per collection + backdrop + decals) must become a playable level
- an existing level scene must be rebuilt after new exports or gameplay changes

## Inputs
- exported FBX per collection, textures, backdrop render, decals, layer contract
- the project's gameplay rig (player, enemies, match/flow, camera) and its builder entry point
- level layout: wave zones, gates, walkable regions, finish area, camera limits, difficulty

## Process
1. **Builder, not hand edits.** One editor menu builder per level (e.g. `BaldNinjAI → 6. Build <Level>`). It recreates the scene from the exports, and manual edits are ported back into it. Gameplay comes from a shared rig function with a per-level layout object (`BuildGameplay(GameplayLayout)`), never a copy of another scene builder.
2. **Axes.** Blender FBX (`-Z` forward, `Y` up, baked) arrives in Unity mirrored on X and Z. Rotate the environment root 180° on Y instead of fixing assets one by one. Probe the bounds once after the first import to confirm.
3. **Materials.** Extract the FBX materials to a project folder once (`AssetDatabase.ExtractAsset`, plus `AddRemap` for shared names) and set them up as URP Lit: base and normal maps matched by name, double-sided for leaves and paper, smoothness per family. Avoid emission on URP Lit for glowing bits; unlit materials plus point lights are cheaper and render reliably.
4. **Layers in the scene.** Static flags on the static layers; the backdrop card is an alpha-clipped unlit quad at real depth; sun, sky and linear fog; a post-processing volume (bloom, ACES, grade, vignette).
5. **Enterable buildings.** Use a cutaway component that hides the camera-facing wall and enables the interior only while the player is inside (the interior costs nothing outside). Add interior lights (embers, windows, light shafts) and smoke as particles.
6. **Walkable height.** Register raised walkable meshes (steps, decks, floors) as ground surfaces with a mesh collider; actors sample the ground height instead of assuming `y = 0`, and flat scenes keep working with no surfaces registered.
7. **Play area.** Give the play area multiple regions, with some unlocked at runtime (e.g. an interior behind breakable doors). The builder authors it, so nothing relies on `Find*` auto-attach.
8. **Breakables and objectives.** Turn each destructible into a breakable component (HP, drop table, initializer wired to the match). Add a door gate that unlocks regions when every door breaks, and a finish area that completes the level once the waves are cleared.
9. **Decals.** Use transparent quads (not alpha-clipped) with the decal textures, parented to the interior so they hide with it.
10. **Difficulty per level.** Wave sets and enemy HP belong to the layout. Tune first levels so a full basic combo knocks out a grunt, and play-test with the owner.
11. **Verify.**
    - With the editor closed, run a batch compile and `-executeMethod` the builder: `Unity.exe -batchmode -quit -projectPath <p> -executeMethod <Builder.Build> -logFile <log>`. The step fails on any `error CS`.
    - Render review shots from the gameplay camera with a capture method; run it without `-nographics`.
    - Generate `.meta` files for new scripts and commit them with the asset.
12. **Commit discipline.** Commit builder code, the generated scene, extracted materials and new `.meta` files together. Commit scenes regenerated by builders after a merge on their own `chore/` branch.

## Outputs
- level builder (menu + batch entry point) and the scene it generates
- reusable runtime components: cutaway, ground height + walkable surface, play-area regions, door gate, level exit
- extracted URP materials, post-processing profile, review renders
- updated TDD tooling table and project plan

## Quality Bar
- the scene is fully reproducible from the builder; no hand-edited scene state is needed
- no per-asset transform fixes; materials look like the Blender review renders
- the player can complete the level end to end (waves, breakable gate, interior, exit) at the agreed difficulty
- batch compile clean; no obsolete-API warnings introduced; review renders checked before handing over

## Common Failure Modes
- copying a whole scene builder per level instead of sharing a gameplay rig with a layout
- forgetting the 180° root rotation and "fixing" assets one by one
- emissive URP Lit materials rendering magenta; alpha-clipped decals losing soft spray edges
- actors pinned to `y = 0` so stairs and raised floors cannot be used
- `Find*`-based play areas, or a single rectangle that blocks interiors forever
- trying batch builds while the editor holds the project lock, or forgetting the scene must be rebuilt after builder changes
